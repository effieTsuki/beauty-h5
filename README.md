# 护肤妆造 H5 · 部署说明

化妆品 / 护肤品收纳应用，架构与「衣橱 H5」完全一致。

## 架构
- **前端**：纯原生 HTML/CSS/JS，零依赖，托管在 GitHub Pages
- **后端**：Supabase（PostgreSQL 存美妆数据 + Storage 存图片）
- **数据隔离**：每台设备首次打开时生成一个 `owner` 标识（存 localStorage），只读写自己的数据；可设置口令，换设备用口令恢复

## 部署三步

### 第一步：初始化数据库（复用衣橱项目即可）
1. 打开衣橱项目同款 Supabase（或新建项目：[supabase.com](https://supabase.com) 注册 → New project）
2. 左侧 **SQL Editor** → New query → 把本目录 `supabase.sql` 内容**整段粘贴** → **Run**
   - 新建 `cosmetics` 表 + `cosmetics` 存储桶，与衣橱的 `clothes` 表、`clothes` 桶互不影响
   - **老库升级**：之前部署过旧版的项目，重跑同一份 `supabase.sql` 即可无损升级（自动补开封状态 / 到期日期两列，并按开封日期回填老数据；历史数据不动）

### 第二步：本地预览
```bash
cd "护肤妆造"
python3 -m http.server 8080
```
浏览器打开 `http://localhost:8080`，或用手机连同一 Wi-Fi 访问 `http://你Mac的IP:8080`。

### 第三步：部署到 GitHub Pages
1. 在 GitHub 新建一个 **public** 仓库
2. 把 `index.html`、`config.js` 推上去（`supabase.sql`、`README.md` 可选）
3. 仓库 **Settings → Pages → Source 选 main 分支** → 保存
4. 等 1~2 分钟，得到网址 `https://你的用户名.github.io/仓库名/`
5. 手机浏览器打开该网址即可使用，数据云端同步、换设备也能看到

> 说明：`anon public key` 是**公开密钥**，设计上就允许放在前端代码里；真正的 `service_role` secret key 千万不要放进任何前端文件。

## 功能清单
- 美妆录入 / 编辑 / 删除，名称、品牌、容量、色号均手动填写
- 图片上传（前端 canvas 自动压缩，省流量省空间）
- 分类筛选：洁面 / 爽肤水 / 精华 / 乳液 / 面霜 / 眼霜 / 防晒 / 面膜 / 卸妆 / 底妆 / 口红 / 眼妆 / 香氛 / 身体护理 / 美发 / 工具 / 其他
- 容量 / 规格：手动输入（如 30ml / 50g / 10片）
- 色号（01 / W03 / 小辣椒）
- **开封状态 + 到期日期**：录入时手动选未开封 / 已开封，可填开封日期；到期日期填包装上的到期日，卡片显示开封/购入时长，到期日 60 天内橙色提醒、超期红色警示
- 状态筛选：状态不限 / 未开封 / 已开封 / 已超期；列表固定按金额从高到低排
- 金额、购入渠道（含免税店 / 代购 / 专柜）、购入时间（默认当天，日历可快速跳年份，也可手输 2024-05-20 / 20240520 / 5-20；到期日期可选未来 10 年）
- 统计：总件数、总金额、已开封数
- 本地快照秒开 + 离线兜底、数据导出（JSON 备份 / CSV 表格）

## 安全说明（重要）
与衣橱一致采用「逻辑隔离」：靠每台设备随机生成的 `owner` 标识区分数据，**适合个人试用**。
数据在**数据库层面并未加密或强制隔离**：理论上拿到项目 URL 的人可通过 API 读取全部数据（美妆数据敏感度有限）。若将来要正式使用，建议升级为「匿名登录 + RLS 行级安全」。
